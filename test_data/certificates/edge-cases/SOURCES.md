## Target list for Phase 0

These cover the "detector must not over-claim" negative cases from
`certificates-strategy/phases-1-2-foundation-detector.md`:

- [ ] `truncated-pem.pem` — valid BEGIN line, truncated mid-base64
- [ ] `corrupt-der-cert.der` — DER sequence that fails BC parse
- [ ] `wrong-magic-looks-like-jks` — `0xfe 0xed 0xfe 0xed` prefix that is
      not a valid JKS
- [ ] `empty.pem` — zero-byte file
- [ ] `whitespace-only.txt` — whitespace, no certificate content
- [ ] `pem-with-blank-lines.pem` — valid cert with extra blank lines
      between header and base64 body
- [ ] `pem-typo-header.pem` — `-----BEGIN CERTIFICAT-----` (detector must
      NOT claim)
- [ ] `der-prefix-not-x509.bin` — `0x30 0x82` prefix that is neither X.509
      cert nor PKCS#12
- [ ] `plain-text.txt` — tests the "detector returns currentMimes
      unchanged" path

## Category floor

Phase 0 coverage guidance: 10 edge-case fixtures.

## Sidecar shape for edge cases

For files the strategy must NOT claim:
- `itemCount` is typically 1 (the file still becomes a GenericFile Item)
- `purls.mustContain: []` (empty)
- `mimeTypes.mustNotContain: ["application/pkix-cert", "application/x-java-keystore", ...]`
  — whichever MIMEs a buggy detector would mistakenly attach
